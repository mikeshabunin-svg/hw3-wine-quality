# Подборка хороших вин

Демонстрация модели Wine Quality из домашнего задания. Проверено с **Python 3.14.0**. Модель в приложении не обучается.

## Запуск

Из папки `wine_app`:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Из корня текущего проекта с уже настроенным окружением:

```bash
.venv/bin/python -m streamlit run wine_app/app.py
```

Откройте адрес из терминала (обычно http://localhost:8501). Приложение строит пути относительно `app.py`, поэтому работает и при запуске из другой директории.

## Возможности

- Ввод 12 признаков; диапазоны и медианы взяты из `test.csv`, цвет вина задаётся переключателем.
- Общий порог в боковой панели, начальное значение — из `config.json` (около 0.268889).
- Матрица ошибок, precision, recall, F1, ROC- и PR-кривые с текущей рабочей точкой.
- Загрузка CSV и скачивание предсказаний. Кнопка примера выдаёт файл с правильными столбцами. Пропущенные столбцы, пустые данные, нечисловые значения и пропуски обрабатываются сообщением в интерфейсе.
- Коэффициенты после стандартизации с объяснением их знака.

CSV содержит `fixed_acidity, volatile_acidity, citric_acid, residual_sugar, chlorides, free_sulfur_dioxide, total_sulfur_dioxide, density, pH, sulphates, alcohol, is_red`. Порядок столбцов может отличаться. `target` нужно исключить; `is_red` равен 0 или 1. Выход: исходные столбцы, `probability`, `prediction` (0/1), `recommendation`.

## Кэширование (4.5)

`load_model` использует `st.cache_resource`: один объект модели разделяется между сеансами и повторными выполнениями приложения. Модель не изменяется после загрузки.

`load_test`, `load_config` и `test_proba` используют `st.cache_data`: кэшируются сериализуемые данные, при получении результата возвращается копия. Аргумент `_model` не хешируется; таблица признаков входит в ключ кэша. Порог не входит в аргументы `test_proba`, поэтому его изменение не вызывает повторный прогноз на test. Пересчитываются метки и метрики. Прогноз для одного введённого вина выполняется отдельно.

Без декоратора `joblib.load` читал бы и восстанавливал модель при каждом действии пользователя. После замены артефактов модели перезапустите сервер или очистите кэш Streamlit.

Документация: [cache_resource](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_resource), [cache_data](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_data).

## Проверка

Приложение проверено через `streamlit.testing.v1.AppTest`: четыре вкладки, 11 числовых полей и выбор цвета вина, начальный порог из конфигурации, пороги 0 и 1, переключение цвета, загрузка корректного CSV и сообщение о недостающих столбцах. Отдельно проверены порядок столбцов, пустой CSV, нечисловые значения, пропуски, бесконечности и недопустимые значения `is_red`. Повторное обращение к кэшу тестовых вероятностей вызывает `predict_proba` только один раз. Проверен запуск сервера из другой рабочей директории.

## Публикация в Streamlit Community Cloud (4.6)

1. Загрузите папку `wine_app` в свой GitHub-репозиторий.
2. Войдите в Streamlit Community Cloud и выберите **Create app**.
3. Укажите репозиторий и ветку. Если файлы приложения находятся в корне репозитория, основной файл — `app.py`; если загружена целая папка — `wine_app/app.py`.
4. В настройках выберите Python 3.14, соответствующий проверенному окружению, и нажмите **Deploy**.
5. После успешного запуска добавьте выданную ссылку в ноутбук.

Если Python 3.14 недоступен в списке сервиса, сначала воспроизведите окружение и проверьте приложение на доступной версии Python. Не меняйте версии scikit-learn/joblib независимо от сохранённой модели: при необходимости пересохраните модель из ноутбука в новом окружении.
